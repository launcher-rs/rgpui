# rgpui 1.8 二次审查（2026-11-21）

对 `main...feat/1.8.0`（94 文件，+12643/−3048）做了一轮独立代码审查，覆盖渲染管线、
文本与输入、窗口帧调度三个高风险子系统。每个发现都逐行核对代码事实，排除误报后，
对确认的问题做了修复并补上回归测试。

## 1. sheet-grid 首字符丢失（已修复）

`SheetGridState::set_editing` 在 input 从 `None` 变 `Some` 时无条件清 `typed_char`，
而 `on_key_down` 的「键入即编辑」刚把首字符存进去。应用响应 `EditRequested` 时
先 `set_editing(Some(cell), Some(input))` 再 `take_typed_char()` 的预期用法会静默丢字符。

**修复**：只在单元格真正切换（或退出编辑）时清 `typed_char`，为同一格绑定输入框时保留。
测试 `set_editing_keeps_typed_char_for_same_cell` 覆盖两种情况。

## 2. SVG 场景动画绕过帧节流（已修复）

`with_max_fps`、失焦省电（30fps）、温控省电（60fps）三档节流，在纯动画帧路径上
恒不生效：动画帧满足 `!force_render && next_frame_callbacks.is_empty()`，旧逻辑直接
返回 `None`，新增的 `animation_interval` 走不到。而 SVG 场景动画恰靠帧末
`request_frame()` 驱动，走的就是这条路。

**修复**：
- 把决策抽成纯函数 `frame_throttle::combine_interval`，有动画间隔时不再短路；
- 节流命中早退会跳过帧末续帧、导致动画卡死——用一次性 timer 按剩余等待时间
  延迟 `request_frame()` 续帧（`animation_frame_pending` 标志防重复排队），既不忙等
  也不卡死。

测试 `animation_frames_are_not_exempt_from_throttling` 覆盖动画帧参与节流、
与省电档取较长间隔、强制呈现不受限等规则。

## 3. opaque quad z-order（已修复，三后端）

D2 深度缓冲只给 quad 分配了深度，非 quad 图元（sprite/path/shadow/underline）关闭
深度测试。opaque quad 在 `draw_scene` 最开头统一绘制。当一个纯色不透明矩形的绘制序
**晚于**一个与它重叠的非 quad 图元时，后被绘制的非 quad 图元错误浮在矩形之上。

这是 D2 提交时已登记在 `borrow-upstream-plan.md` 的未移植项（「非 quad 批视口深度
游标」）。

**修复**：移植上游 zed `be07e43ea0` 的视口深度游标——维护 `quad_cursor`，每画一个
Quad 批推进；非 Quad 批把视口深度范围钉在 `quad_depth(cursor)`，深度态从「禁用」
改为 `Greater`（测不写）。落在不透明矩形之后的整批片元在深度测试处被剔除。
三后端同步：
- wgpu：`pass.set_viewport(..., depth, depth)`，非 quad 管线深度态改 Greater；
- Windows D3D11：`BatchRenderer.viewport` 的 `MinDepth=MaxDepth` 按批调整；
- macOS Metal：`MTLViewport.znear=zfar` + encoder 深度态。

各端加端到端像素测试：先画红下划线、后画覆盖它的不透明绿矩形，断言像素为绿
（`headless_opaque_quad_occludes_earlier_underline` / `opaque_quad_occludes_earlier_underline`）。

## 4. 嵌套 paint_layer（确认为误报）

子代理报告称嵌套 layer 时图元按 layer 队列分组落地、破坏「图层叠在 f 后续内容之上」
的承诺。构造 A（外层前）/B（子层）/C（外层后）三者重叠的场景实测，绘制序为
A < C < B——子层 B 正确叠在外层后续内容 C 之上。现有 `pop_front`（外层先落地、
内层后落地）使内层获得更大 order，行为正确。新增
`test_nested_layer_child_sits_above_outer_later_sibling` 作为回归保护。

## 5. dispatch_action 光标隐藏（记录，未改）

`App::dispatch_action` 改走 `dispatch_action_now`，跳过了键盘命令触发的
`hide_cursor_until_mouse_moves` 副作用。属小范围行为差异，无稳定复现与明确验收标准，
本次不动，留作后续评估。

## 6. 外部项目实测反馈（rujian 图片编辑器）

其他项目使用 1.8 后报告：图片编辑器的浮动工具条白色圆角背景只覆盖约 232px
（像素扫描白色区仅 x=16..249 与 x=1250..1482），而线宽滑杆、文字底色等子控件
延伸到 x≈717，直接叠在图片渐变上、可读性变差；与旧版二进制对照背景是完整的。

**版本核对**：该反馈对应的 rujian `Cargo.lock` 锁定在 `924299dab4`——即本轮修复
**之前**的 1.8 快照。工具条背景是 `rounded(6).bg(SURFACE).border_1()` 的圆角矩形，
经 `insert_quad` 拆成「内部不透明矩形 + 四条边带」：内部矩形走不透明通道、边带
走混合通道。若内部矩形被先画的非 quad 图元（图片 quad / Surface）覆盖，就只剩
两端边带可见——与「白色仅在两端、中间缺失」的现象一致，正是第 3 项 z-order 问题
的表现。**本轮第 3 项修复可能已覆盖该回归**，但无头环境无法 GUI 实测，需 rujian
更新 lock 到本轮修复后的提交（≥ `cef27aa9a5`）后重新观察确认。

其余外部反馈与本项目核对结论一致：
- 破坏性 API 共 5 类（Path 去泛型、paint_layer 去 bounds、MonochromeSprite.pad→
  animation、lyon→lyon_path、UAX #14 软换行语义），rujian 只命中 Path 去泛型一项，
  且已迁移完成（`rgpui::Path<Pixels>` → `rgpui::Path`）；其余 grep 无调用点。
- 上游已披露遗留（UAX #14 批量换行慢 2.4–3.6×、长描边 CPU 2–8×、X11 SVG 动画
  不连续、GPU 数据未复测）与 `1.8-vs-1.7-upgrade.md`「已知遗留」一致；本机性能
  基线见 `local-perf-baseline.md`（老电脑端到端 FPS 1.8 不慢于 1.7）。
- D4 部分重绘在 Windows 软适配器默认开启，`RGPUI_PARTIAL_REDRAW=0` 可关闭——
  若 GUI 观察到异常，可用该开关做 A/B 定位。
