# 1.2.0 组件设计文档

> 灵感来源：gpui-kit（37 组件目录）为参照，shadcn、Ant Design（含 AntDX AI 组件）
> 找好用的。gpui-kit 没有但好用的也加。全部直接进 `rgpui` 现有目录，不建新 crate。
> 约定：中文文档注释；builder 风格；`Styled`/`Sizable` 等现有 trait；中文注释覆盖所有公开项。
> 开发计划与验收见 `1.2.0-dev-plan.md`；非目标统一收录在 `1.2.0-dev-plan.md`。

## B1. Sidebar（`components/sidebar.rs`，新建）

导航侧边栏（对标 shadcn Sidebar / AntDX Conversations 承载体）。

```rust
pub struct Sidebar { items: Vec<SidebarItem>, selected: Option<SharedString>, collapsible: bool, collapsed: bool, on_select: Option<Rc<...>> }
pub struct SidebarItem { id: SharedString, label: SharedString, icon: Option<IconName> }

impl Sidebar {
    pub fn new() -> Self;
    pub fn item(mut self, id: impl Into<SharedString>, label: impl Into<SharedString>, icon: Option<IconName>) -> Self;
    pub fn selected(mut self, id: impl Into<SharedString>) -> Self;
    pub fn collapsible(mut self, collapsible: bool) -> Self;
    pub fn on_select(mut self, handler: impl Fn(&SharedString, &mut Window, &mut App) + 'static) -> Self;
}
// RenderOnce 即可（状态由父持有），selected 变化父 cx.notify()
```

## G1. Dock 布局（`components/dock.rs`，新建）

**原因**：VS Code / Zed 级 IDE 都靠 Dock 组织工作区（文件树 + 编辑器 + 终端 + 问题面板），
ru_editor 这类应用现在只能手写 `v_flex`/`h_flex` 硬编码布局，面板拖不动、关了恢复不了。
**好处**：应用只需声明“有哪些面板”，拖拽停靠/标签切换/布局持久化框架全包，IDE 类应用开箱即用。

```rust
pub enum DockPosition { Left, Right, Bottom, Center }
pub struct DockPanel { id: SharedString, title: SharedString, position: DockPosition, content: AnyElement, closable: bool }
pub struct DockAreaState { panels: Vec<DockPanel>, sizes: ..., active_tabs: ... }
// 状态实体（Render），面板拖拽经现有 Draggable/DropZone + TabDragState 实现同组标签排序；
// 布局序列化：positions + sizes + active_tab 存 JSON，启动时恢复。
```

## G2. Editor（不建新组件，input `CodeEditor` + tree-sitter 后端）

**原因**：`input_ui` 的 `CodeEditor` 外壳已完备（行号/折叠图标 UI/缩进线/display_map 投影层），
空的只是两个数据源——fold 候选（`folding.rs`  stub 返回空）与高亮实现（`Highlighter` trait 无实现）。
另起 editor 组件会分叉第二套文本状态（选区/滚动/编辑），长期维护两套必烂。
**好处**：复用现有编辑行为零回归；tree-sitter 只做语法分析后端，经 `Highlighter` trait 注入，
wasm 下自动降级 `NoHighlightStyles`；语言按子 feature 拆分，不用的语言不编译。

```rust
// crates/rgpui/Cargo.toml
tree-sitter = ["dep:tree-sitter-rust"]  # 默认关，#[cfg(all(not(target_family = "wasm"), feature = "tree-sitter"))]
pub struct TreeSitterHighlighter { ... } // impl Highlighter（update/styles/fold_ranges_for_edit）
impl InputState { pub fn set_highlighter(&mut self, h: Arc<dyn Highlighter>, ...) } // 接 display_map
```

## G3. Sidebar 增强（`components/sidebar.rs` 加三件）

**原因**：现有 Sidebar 只是“应用导航栏”（id/label/icon + 折叠），IDE 侧边栏的分组、
未读数、折叠分组都没有，ru_editor 切过去不够用。
**好处**：补 `section` 分组头 + 可折叠分组 + `badge` 计数即达 IDE 基线；拖拽排序涉及手势大改，1.2 不做。

## G4. SearchPanel 老版删除（`components/search_panel.rs` 删 370 行）

**原因**：老 `SearchPanel`（RenderOnce）构造要 `&mut Context<Self>` 却无法被父长期持有，
实质不可嵌入；且回调全是空实现（替换按钮误调 next_match）。零调用方，留着只会误导新人。
**好处**：删后新版 `SearchPanelState` 补 `on_close` + `Styled` 两行 builder 即 100% 平替，
API  surface 减半，维护只剩一条路。

## G5. `cx.debounce` 方法版（`App`/`Context` 便捷方法）

**原因**：`Debouncer` 结构版要求调用方自持实例 + 自传 executor，搜索框这种“每次输入都防抖”
的高频场景样板代码多。方法版把实例挂 `App` 全局注册表，一行调用。
**好处**：`cx.debounce("search", duration, callback)` 一行搞定，key 隔离多路防抖；
结构版保留给需要独立生命周期的场景。

## G6. Upload（`components/upload.rs`，新建）

**原因**：平台原生文件对话框三桌面端全有（`prompt_for_paths`），缺的只是 UI 层——
拖拽区 + 文件列表 + 进度，现在每个应用都要手写一遍。
**好处**：纯 UI 组件 + 现有平台对话框对接，桌面端零新增平台代码；Web 明确降级
（`<input type=file>` 或纯展示），不阻塞。

## G7. Mermaid 子集（`components/mermaid.rs`，新建，flowchart LR/RL）

**原因**：文档/ COT 思维链（ThoughtChain）经常要画流程图，现在只能贴静态图。
完整 Mermaid 无依赖可用，但流程图 80% 场景 = 矩形/菱形 + 直线箭头 + 文本。
**好处**：手写子集解析（`A-->B`、`A{判断}`、`A[矩形]`）+ 现有 quad/line 原语布局渲染，
零新依赖；完整语义（子图/曲线边）明确不做，文档写清边界。

## G8. Carousel（`components/carousel.rs`，新建）

**原因**：展示型应用（story/官网/引导页）轮播是刚需，现在只能手写定时器切索引，
指示器/手势/循环样板每个应用重复写。
**好处**：`index + autoplay + loop + 指示器 + 滑动手势` 一次封装（约 300 行，
动画/滚动地基现成），展示类示例直接复用。

## G9. 聊天三件（`chat/`：Bubble / MessageScroller / Marker）

**原因**：B10 七件补的是“消息8462”，但聊天的“容器层”还是裸的——`ChatView` 只是
`v_flex` 裸文本，无气泡样式、无滚动吸底、无时间/未读分隔线，AI 对话应用撑不起来。
**好处**：`Bubble`（左右气泡 + 头像 + 圆角）+ `MessageScroller`（吸底 + 新消息浮标，
包一层滚动容器）+ `Marker`（时间/未读分隔线），ChatView 升级为可直接落地的对话容器。

## H. Input 右键菜单（`input_ui/context_menu.rs`，新建 + `state.rs`/`input.rs` 改三处）

**原因**：搜索标记（`TextDecorationCollection` + `SearchHighlight`）补齐了“读”，
但 input 右键只移动光标、不弹菜单——剪切/复制/粘贴全靠背快捷键，新用户上来就懵。
**好处**：默认菜单开箱即用；三档定制由简到繁，与 `Tree::context_menu` 同模式
（builder 存 state、渲染时包 `.context_menu`），学一处会两处。

默认菜单（按状态自动禁用，不可点但仍展示）：

| 菜单项 | 动作 | 禁用条件 |
|--------|------|----------|
| 剪切 | `Cut` | 无选区 / 输入框禁用 |
| 复制 | `Copy` | 无选区 |
| 粘贴 | `Paste` | 输入框禁用 |
| 全选 | `SelectAll` | 文本为空 |
| 撤销 | `Undo` | 无撤销栈 / 输入框禁用 |
| 重做 | `Redo` | 无重做栈 / 输入框禁用 |

```rust
pub type InputContextMenuBuilder =
    Rc<dyn Fn(PopupMenu, Entity<InputState>, &mut Window, &mut App) -> PopupMenu>;

// Input 元素层（三档，写入共享 InputState，粘性，后设置的生效）
Input::new(&state).show_context_menu(false);              // 1. 总开关
Input::new(&state).context_menu_extra(|menu, _, _, _| menu);    // 2. 追加（默认保留，自定义跟分隔符后）
Input::new(&state).context_menu_override(|menu, state, _, cx| { // 3. 接管（默认不要）
    let menu = InputState::build_default_context_menu(menu, &state, cx);
    menu.separator().menu("我的动作", Box::new(MyAction))
});
// InputState 层同名方法（builder 版创建时用 + set_* 版创建后改 + clear 恢复默认）
impl InputState {
    pub fn build_default_context_menu(menu: PopupMenu, state: &Entity<InputState>, cx: &App) -> PopupMenu;
    pub fn has_selection(&self) -> bool;  // 另有 is_empty / is_disabled / can_undo / can_redo
}
```

约束：菜单挂在 `InputState::render` 的文本区上（单行/多行/CodeEditor 全覆盖，
裸 `Entity<InputState>` 直渲染同样生效；前缀/后缀装饰区不触发）；
动作用 `input` 命名空间原生 action（`Copy`/`Cut`/`Paste`/`SelectAll`/`Undo`/`Redo`），
经触发器祖先链冒泡到 `Input` 外层已注册的 `on_action`，无需额外接线。
