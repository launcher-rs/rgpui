# 1.2.0 编辑器分拆设计（Input 表单 / Editor 编辑器 / TextCore 共享核）

> 决策状态：已决定分拆（"杀鸡不用牛刀"），本方案为执行依据。
> 约束：开发阶段，直接改不做兼容；每阶段 `cargo test -p rgpui` 全绿 + 中文 IME 手测。

## 0. 结论先行

抽 **TextCore 共享核** + 组合（`InputState` / `EditorState` 各持有一份），**不复制**。
顺序：P0 feature 门（几天）→ P1 抽核（1~2 周）→ P2 渲染分层（1~2 周）→
P3 Editor 落地 + `code_editor` mode 退役（1 周）。`crate` 化暂不做，
先模块后 crate（外部复用出现时再提）。

## 1. 动机量化

`InputState` 公开方法约 70 个：表单专属约 20（masked/pattern/validate/
number/step/min/max/loading/mask…），编辑器专属约 25（fold/行号/行注释/
auto_close/bracket_match/current_line/document_symbols/goto_symbol/
set_highlighter/reveal_*/multicursor/line_ops…），共享约 25。
表单用户为 20 个方法拖进 25 个编辑器方法——分拆不是洁癖，是 API 事故。

## 2. 现状盘点（分拆可行性证据）

1. **特性实现已是独立文件 + `pub(super)`**：line_ops/multicursor/auto_close/
   bracket_match/current_line/context_menu 全是模块内方法，对外只有
   state.rs 里十几个 builder——搬运边界现成，无需解纠缠。
2. **消费方只用基础 API**：combobox/sender/tag_input/otp/search_panel 等
   12 个消费方全是 `new + placeholder + 单行行为`，分拆后原地不动。
3. **渲染是 mode 分支不是交织**：`element.rs` 约 20 处
   `is_single_line/is_code_editor` 开关，拆渲染就是把分支掰成两个函数。
4. **trait 扩展模式已跑通**：`Highlighter::document_symbols` 默认空实现，
   tree-sitter 后端覆盖；`TextDecorationCollection` 被 bracket/current_line/
   search 三家复用；`actions!` + keymap 加新动作不动分发。

## 3. 可扩展性设计（编辑器功能只会越来越多）

未来功能（minimap/vim/snippets/inlay hints/sticky scroll）必须满足：
**加新能力只加新文件，不改核心文件**（开闭原则）。已验证可用的机制继续用，
缺的三件本次补齐：

### 3.1 已有机制（沿用，写进规范）

- 能力 trait：`Highlighter`（语法/折叠/大纲数据源），新后端实现 trait 即可；
- 装饰集合：任何行内标记走 `TextDecorationCollection`，不碰渲染；
- 动作键位：`actions!` + keymap 上下文，新动作自带默认键与文档；
- 投影复用：`DisplayMap` 折叠投影给所有需要行映射的功能共用。

### 3.2 缺失机制（本次补齐，否则每个新功能都是一次 IME 式事故）

1. **编辑 funnel 单一化**：现状两入口（`replace_text_in_range` /
   `replace_and_mark_text_in_range`）。高亮刷新曾只接前者、漏掉后者，
   直接导致中文输入崩溃（见 1.2 修复记录）。规范：文本变更只走一个 funnel
   出口，新功能不许各自接线。
2. **`on_edit` 订阅表**：funnel 出口统一触发 `Vec<EditHook>`（只读快照），
   bracket/current_line/highlight/multicursor 的刷新逻辑从"改 funnel 代码"
   改为"订阅 hook"。新增功能默认走订阅，duplicate 刷新用合并标记去重。
3. **类型化扩展存储**：`extensions: HashMap<TypeId, Box<dyn Any>>` +
   `ext::<T: Default>()`（抄 `App::globals_by_type` 现成模式）。
   新功能状态一律进扩展表，`InputState` / `EditorState` 结构体不再膨胀。
4. **渲染覆盖层列表**：gutter/折叠图标/空白符/minimap（未来）注册为
   overlay 渲染函数，共享同一份布局数据，不再各自改 `prepaint`/`paint`。
5. **keymap 上下文约定**：特性动作统一 `"Input"` 上下文（现状），vim 等
   模态需求预留 `"input:vim:<mode>"` 命名空间；新增默认键必须附 keymap
   冲突单测（`keymap.rs` 现有测试即模板）。

### 3.3 可维护性红线（写进 AGENTS 备查）

- `state.rs` 单文件超 3000 行即触发再拆分（本次 P1 后应回落到 2000 内）；
- 新编辑器功能必须自带：独立文件 + `pub(super)` 实现 + builder 开关 +
  中文文档注释 + 与 multicursor/undo/IME 交互的单测；
- 特性组合矩阵：multicursor ×（auto_close/电缩进/粘贴）已明确不扇出，
  后续每对交互必须文档注明（是特性还是 bug，只差这一行字）。

## 4. 目标架构

```text
input_ui/
  core.rs        ← 新抽：TextCore（Rope + 选区/光标 + History + 基础编辑/撤销
                   + IME + 剪贴板 + on_edit hooks + extensions 表）
  state.rs       ← 瘦身后 InputState { core + 表单字段 }（校验/掩码/number/password）
  editor.rs      ← 新建：EditorState { core + gutter/折叠/多光标/大纲… }（字段能进
                   extensions 表的不进结构体）
  input.rs       ← Input 组件（表单渲染，不变）
  editor_ui.rs   ← 新建：Editor 组件（gutter/折叠/行号 + overlay 列表）
  line_ops.rs / multicursor.rs / auto_close.rs / … ← 实现平移到 EditorState，
                   方法签名不变（self 类型换一下）
```

组合不复制：`EditorState` 持有 `TextCore`，`Deref<Target = TextCore>` 保证
`text()` / `replace()` 等调用姿势不变；`entity.update` 边界处用显式 delegate
（`Context<EditorState>` 与 `Context<TextCore>` 不互通，这是唯一的手工活）。

## 5. 分阶段计划

- **P0（几天，1.2 可发）**：`editor` feature 门（8 个编辑器模块 + 25 个方法），
  表单构建立刻瘦；零行为变化。
- **P1（1~2 周）**：抽 `TextCore` 纯结构 + 独立单测；`InputState` 改持有关联；
  对外 API 一个不改；门禁：500+ 单测全绿 + state.rs 回落 2000 行内。
- **P2（1~2 周）**：渲染分层（核心文本渲染 + editor overlay 列表 + 表单 chrome），
  `element.rs` 20 处分支掰开；门禁同上 + 示例视觉无回归（story/editor/search 跑一遍）。
- **P3（1 周）**：`EditorState` + `Editor` 组件落地；editor 示例迁移；
  `InputMode::CodeEditor` 直接删除（开发阶段不兼容）；12 个消费方复查（预期零改动）。
- **全程红线**：每阶段 `cargo test -p rgpui` 全绿 + 中文 IME（组字/中英混输/
  删词）手测 + `cargo clippy -p rgpui --all-targets -- -D warnings`。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 选区/光标与编辑 ops 交织最深，切分线画错全崩 | P1 先定 `TextCore` 字段清单并评审；`backspace/replace` 首批搬运+单测锁定 |
| 渲染分层破坏软换行/折叠投影 | P2 只搬不改逻辑，逐个 overlay 开关对比（特性开关全关 = 原样） |
| 外部 12 消费方被动 | P1/P2 对外 API 冻结，P3 只动 CodeEditor 用户；ru_editor 发迁移说明 |
| 工期膨胀（估计 4~6 周） | P0 独立交付先止血；P1 后可暂停，架构已收敛一半 |

## 7. 决策记录

- 不复制：8000 行共享核复制两份，等于买双倍 bug（IME 三连 panic 教训）。
- 先模块后 crate：`crate` 化等 rgpui 之外的复用出现再提，现在拆包只有成本。
- `CodeEditor` mode 退役不兼容：开发阶段，直接删（既定规则）。
- `TextArea` 缺失（AGENTS 索引有、代码无）：P3 时按多行表单补，归 Input 侧。
