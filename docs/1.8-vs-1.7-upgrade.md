# rgpui 1.8 对比 1.7：性能提升、不兼容变更与升级指南

> 对比基线：`v1.7.0`（`ced6fa09`）→ `feat/borrow-upstream`（2026-11-21）。
> 共 57 个提交，核心库 `crates/rgpui/src` +5982/−1104 行。

## 一、性能对比（本机实测）

> **本机实测**（Windows，2026-11-21，criterion 基准，v1.7.0 worktree 对照）：
>
> | 基准 | 1.7.0 | 1.8（本分支） | 变化 |
> |---|---|---|---|
> | `scene_build/layout/uniform_list` | 268–270 µs | 255–258 µs | **≈4–5% 更快**（D1 合批 + 排序加速的合计效果） |
> | `scene_build/layout/divs` | 3.55–3.57 ms | 3.59–3.63 ms | 持平（噪声内） |
> | `text_wrap/wrap_latin`（1 万行） | 6.7–7.0 ms | 24.5–24.8 ms | **≈3.6× 变慢**（B3 UAX #14 接线的代价，见下） |
> | `text_wrap/wrap_cjk`（1 万行） | 6.8–7.0 ms | 16.4–16.6 ms | **≈2.4× 变慢**（同上） |
>
> **text_wrap 变慢的根因**（已定位）：B3 接线后每行软换行都要对全行文本跑一次
> `icu_segmenter` 分段（`segment_str` 实测 0.66 µs/行，分段器构造本身可忽略），
> 这是 UAX #14 完整规则的固有成本——旧 `is_word_char` 是逐字符 O(n) 类别查表，
> UAX #14 要维护 40+ 类 pair 状态机。上游 commit 自述 "not as performant as
> is_word_char, but still plenty fast enough"。对交互式编辑（单行/视口行）无感；
> 对**批量软换行**（大文档全量重排、导出）是可感知的回归，升级时需评估。
> C2 的增量重换（`rewrap_changed_widths`）可部分抵消——拖分隔条场景只重换
> 受影响行，未受影响的行不走分段器。
>
> **其余改动的本机验证状态**（端到端 FPS 对比见 `docs/local-perf-baseline.md`）：
>
> | 改动 | 验证状态 |
> |---|---|
> | **D1 图元批处理**（`02b3f010`） | ✅ 单测断言（本机基准见上表 uniform_list） |
> | **D2 深度缓冲 anti-overdraw**（`e68a36cc`） | ✅ wgpu 回读 + 软件适配器端到端 |
> | **D3 环绕数路径渲染**（`f3c9a63d`） | ✅ 三后端 + 软件适配器端到端 |
> | **D4 软适配器部分重绘**（D4a–D4c） | ✅ 默认开启（D4c 逐像素对拍通过） |
> | **场景排序加速**（`b5e28c7e`） | ✅ 单测逐位一致（本机合计见上表） |
> | **SVG 场景层动画**（`c80661dc`） | ✅ 单测 8 条 |

## 二、不兼容变更（升级必看）

### B1. `Path` 去泛型（D3，破坏性最大）

```rust
// 1.7
let path: Path<Pixels> = ...;          // Path<P> 泛型 + 预镶嵌三角形
window.paint_path(path, color);        // paint_path(Path<Pixels>)

// 1.8
let path: Path = builder.build()?;     // 非泛型 = Arc<[PathCurve]>，只能由 PathBuilder 构建
window.paint_path(path, color);        // paint_path(Path)
```

- **删除**：`Path::new` / `push_triangle` / `Path::scale` / `PathBuilder::build_path` / `PathId` / `PathVertex`
- **改型**：`StrokeOptions`/`FillOptions` 从 lyon 重导出改为自有类型——`with_line_width` / `with_line_cap` / `with_line_join` builder 方法**保留**，现有调用点不动；新增 `FillOptions::with_fill_rule`
- **迁移**：直接构造 `Path` 的代码改走 `PathBuilder`（`PathBuilder::fill()` / `stroke(width)` + `move_to`/`line_to`/`curve_to`/`arc_to`/`add_polygon` + `build()`）；`paint_path` 签名从 `Path<Pixels>` 改 `Path`

### B2. `paint_layer` 去 bounds 参数（D1）

```rust
// 1.7
window.paint_layer(bounds, |cx| { ... });
// 1.8
window.paint_layer(|cx| { ... });   // 边界由场景按图层内容自动计算
```
`Scene::push_layer` 同步去掉 `bounds` 参数。仓内调用点已同步；外部直接调用这两个 API 的代码需删 bounds 实参。

### B3. `MonochromeSprite.pad` → `animation` 字段（SVG 动画）

`MonochromeSprite { pad: 0, ... }` 改为 `MonochromeSprite { animation: SpriteAnimationId::NONE, ... }`。结构体大小/布局不变（都是 u32），但**字段名变了**，直接构造 MonochromeSprite 的代码要改字段名。`SpriteAnimationId::NONE` = 无动画。

### B4. 依赖变化

- `lyon = "1.0"` → `lyon_path = "1.0"`（rgpui 直接依赖；`lyon` 仍可从 showcase 等示例用）
- 新增 `tiny-skia-path = "0.11"`（描边/虚线展开，已进 Cargo.lock）
- `rgpui-markdown` 依赖切换为自维护 `mermaid-renderer 0.1.1`（mermaid feature）

### B5. 非破坏但值得注意的语义变化

| 变化 | 影响 |
|---|---|
| **UAX #14 软换行**（`93169833`） | 连字符后可断（LB21）、URL/路径中 `/` `?` 可断、emoji 序列不再被拆开、半角 ASCII 标点不再有“单词字符”豁免——**换行位置可能与 1.7 不同**，对布局敏感的集成需回归 |
| **描边 CPU 变慢 2–8×**（D3 取舍） | 长笔画（ink 自由笔迹、复杂 SVG stroke）CPU 侧变慢；GPU 侧大幅下降。笔迹密集场景需实测 |
| **reduce motion**（`c80661dc`） | `Svg::with_timed_transformation` 在 `cx.reduce_motion()` 开启时静态绘制；系统「减少动态效果」会禁用 SVG 动画 |
| **动画时钟**（`956454d8`） | 动画时间基准从 `Instant::now()` 换成 executor 时钟；测试时钟下动画行为改变（生产一致） |
| **DataFrame 样式** | 新增 `GutterStyle`（行号沟槽样式可配）、折叠 API（`fold_all`/`unfold_all`/`fold_at_level`）、IME 失焦结束组合、sheet-grid 合并单元格/拖拽/双击重置行高、`TimedTransformation` 动画——**纯新增**，无破坏 |
| **帧间隔** | `WindowOptions` 新增 `inactive_frame_interval`/`thermal_frame_interval`，默认值与旧硬编码一致（30fps/60fps），行为不变 |

## 四、升级步骤

1. **依赖**：`cargo update -p rgpui --precise <1.8>`（或改 Cargo.toml `rgpui = "1.8"`）；确认 `lyon` 依赖如有直接引用需改 `lyon_path`（或直接去掉，PathBuilder 已封装）。
2. **编译错误修复**（按编译器提示）：
   - `Path<Pixels>` → `Path`（类型标注）；直接 `Path::new` 等 → `PathBuilder`
   - `paint_layer(bounds, ...)` → `paint_layer(...)`
   - `MonochromeSprite { pad: ... }` → `{ animation: SpriteAnimationId::NONE, ... }`
   - `StrokeOptions`/`FillOptions` 的 lyon 特有字段（如 `tolerance`）→ 检查自有类型是否覆盖；未覆盖的用 `PathBuilder` 的曲线近似（0.25px 容差）
3. **行为回归**：
   - 软换行位置变化（UAX #14）→ 对比关键页面的换行
   - 笔迹/描边 CPU 热点 → profile（长笔画 2–8×）
   - macOS：Metal shader 由 CI 验证；本地 `cargo check -p rgpui-macos` 不编译 shader
4. **新能力按需启用**：
   - `Svg::with_timed_transformation(TimedTransformation::rotation(...))` 做低 CPU 动画
   - `EditorState::set_gutter_style(GutterStyle)` 自定义行号沟槽
   - `InputState::fold_all`/`fold_at_level` 折叠
   - `SheetGrid` 合并单元格 / `ResetRowHeight` 事件
5. **验证**：`cargo test -p rgpui --test guards`（组件索引/覆盖表/fence 守卫）、`cargo clippy --workspace --all-targets -- -D warnings`、跑一遍 showcase。

## 五、已知遗留

- **text_wrap 3.6×/2.4× 变慢（本机实测）**：UAX #14 分段的固有成本（0.66 µs/行 vs 旧类别查表）；批量软换行场景需评估，交互式编辑无感；C2 增量重换可部分抵消
- **X11 的 SVG 动画**：`PlatformWindow::request_frame` 未实现，动画不连续（需要异步重绘请求，登记在计划文档）
- **描边 CPU 2–8×**：长笔画（1000 点自由笔迹约 1.5ms vs 0.2ms）为上游已声明取舍，笔迹密集应用需实测
