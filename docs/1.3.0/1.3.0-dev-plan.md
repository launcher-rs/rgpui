## I. 检查器完善（Inspector）

> 背景：1.2.x 期间以 `examples/inspector/` 验证了检查器四件套
> （开关面板 / 面板 UI / 拾取 / 状态展示）与祖先链树脊、长链折叠、
> 节点复制路径。但仍有四块短板，本版本补齐。

- [ ] I1. **树节点 ↔ 界面区域双向映射**（点击树选中画布元素并高亮）。
      现状卡点（已验证）：选中需要完整的 `InspectorElementId`
      （含该祖先的源码位置 + 实例号），外部合成不出来；
      非激活元素的 `DivInspectorState` 在绘制时即被丢弃，只保留当前选中的；
      `Inspector::select` 仅 `pub(crate)`。
      方向：当前帧 `inspector_hitboxes` 注册表按全局路径前缀反查祖先 id，
      以 hitbox 包含关系消歧同路径多实例；新增公开 API
      （如 `Inspector::select_ancestor(levels_up)`），复用拾取高亮绘制选中区域。
      验收：点击树任一节点 → 画布对应区域高亮 + 面板显示该节点源码位置与布局边界。

- [ ] I2. **完整元素树 + 逐节点折叠/展开**。
      现状卡点（已验证）：即时模式框架每帧后不保留完整元素树，
      帧内只剩扁平 hitbox/图元；当前面板仅渲染选中元素的祖先链树脊，
      示例侧长链折叠（8 层阈值）只是过渡。
      方向：调研 prepaint 期保留 parent→children 映射的代价
      （仅检查器打开时保留，关闭即丢；量大时复用 `VirtualList`）。
      验收：面板内完整树可逐节点展开/折叠；检查器关闭时零额外开销
      （默认构建不受影响，跑已有性能测试确认）。

- [ ] I3. **检查面板内置化**（默认面板，开箱即用）。
      现状：每个应用手写 `set_inspector_renderer` + 状态展示约 200 行
     （见 `examples/inspector/`），接入门槛高。
      方向：框架提供默认面板（状态徽标、拾取按钮、源码位置、祖先链树、
      `DivInspectorState` 布局信息）；`toggle_inspector` + 默认渲染器两行启用；
      `examples/inspector/` 瘦身为“开关演示 + 一处自定义展示”。
      验收：新建空窗口两行代码出完整面板；inspector 示例行数明显下降且行为一致。

- [ ] I4. **面板自定义接口文档化**。
      现状：`set_inspector_renderer`（整板替换）与
      `register_inspector_element`（按状态类型扩展）已有但缺文档与范例。
      方向：明确两接口分工与 recipe（何时整板替换、何时局部扩展）；
      `rgpui-book` 新增检查器章节；`examples/inspector/` 保留一份自定义面板
      作为 living recipe；Header/Section 插槽化列为可选，不阻塞发布。
      验收：文档 + 示例可照抄；第三方自定义面板无需改库。

## C. 回调签名统一（on_click / on_change / on_select）

> 来源：AI 升级 rgpui 实战反馈——各组件回调签名没有一致规律，
> 迁移调用点需逐个查签名。经普查确认属实，三个维度全乱：

> | 组件 | 现状签名 |
> |------|----------|
> | `Button` / `Tab::on_click` | `Fn(&ClickEvent, &mut Window, &mut App)` |
> | `Checkbox` / `Switch` / `Radio::on_click` | `Fn(&bool, …)`（引用） |
> | `RadioGroup` / `TabBar::on_click` | `Fn(&usize, …)`（引用；与 `Tab` 同名不同义） |
> | `BreadcrumbItem::on_click` | `Fn(&mut Window, &mut App)`（无事件无值） |
> | `Select::on_change` | `Fn(usize, &SharedString, …)`（值+引用混用） |
> | `Pagination` / `Rate` / `ColorPicker` / `DatePicker::on_change` | `Fn(usize / f32 / Hsla / NaiveDate, …)`（按值） |
> | `Carousel::on_change` | `Fn(usize, usize, …)`（两值） |
> | `Combobox` / `TagInput` / `Upload` | `Fn(&[…], …)`（切片引用） |
> | `Sidebar` / `Upload` / `NavigationMenu::on_select` | 值变更却叫 `on_select` |
> | 线程界限 | elements 系 `Rc`（无 `Send + Sync`），多数 components 系 `Arc + Send + Sync`，`Carousel` / `Upload` / `TagInput` 又无界限 |

- [ ] C1. **统一约定并全量迁移**（breaking，按仓库约定直接改，不留兼容）：
      纯点击一律 `on_click: Fn(&ClickEvent, &mut Window, &mut App)`
     （`BreadcrumbItem` 补事件参数）；值变更一律改名 `on_change`，
      签名 `Fn(Value, &mut Window, &mut App)`，值一律按值传递
     （`bool` / `usize` / `f32` / `Hsla` / `NaiveDate` / `SharedString` / `Vec<T>`；
      现有 `&bool` / `&usize` / `&SharedString` / `&[T]` 一律改按值，
      `SharedString` / `Vec` 均为 Arc-backed 廉价克隆，回调同步执行无生命周期问题）；
      存储统一 `Arc` + `Send + Sync + 'static`（向严格方向统一，`Entity` 捕获不受影响）。
      涉及约 15 个组件
     （`button` / `checkbox` / `switch` / `radio` / `breadcrumb` / `tab_bar` /
      `select` / `pagination` / `rate` / `carousel` / `color_picker` /
      `date_picker` / `combobox` / `tag_input` / `upload` / `sidebar` /
      `navigation_menu`）及 `rgpui_story` / 全部示例 / 相关 tests 的调用点同步。
      验收：上表逐项对号入座；`cargo test --workspace` 全过；
      `rgpui-book` 回调章节更新（命名 + 签名 + 线程界限三条规则）。
