# rgpui v1.1.0 开发计划

基于 ru_editor 开发体验问题记录、Velotype 深度分析、gpui-kit（原 gpui-component）功能对标，提炼 rgpui 核心框架的改进目标。

---

## 一、问题分析总结

### 已有功能（无需修复）

| 功能 | 状态 | 位置 |
|------|------|------|
| 命令面板 | ✅ 已有 | `components/command_palette.rs` |
| 代码缩进指示线 | ✅ 已有 | `input_ui/indent.rs`，`indent_guides: true` |
| 托盘图标 ICO/PNG | ✅ 已支持 | `tray.rs` 的 `create_hicon_from_bytes` |
| 托盘菜单子菜单/Toggle | ✅ 已有 | `tray.rs` 的 `TrayMenuItem` |
| SortableList | ✅ 已有 | `components/sortable_list.rs` |
| 迁移指南 | ✅ 已有 | `docs/migration-guide-from-rgpui-component.md` |

### 不修复的问题

| 问题 | 原因 |
|------|------|
| Entity 与 Global | Rust 设计限制，newtype 模式是标准做法 |
| ru_editor 特定功能 | 属于应用层，不在框架层实现 |

### rgpui 与 gpui-kit 功能差距分析

| 功能 | gpui-kit | rgpui 现状 | 差距等级 |
|------|----------|------------|----------|
| LSP 集成 | 完整客户端（补全/悬停/跳转定义/代码操作/语义令牌/文档颜色） | `lsp-types` 仅在 workspace 声明，无任何代码 | 🔴 严重 |
| 语法高亮 | Tree-sitter 30+语言，注入支持，语言注册表 | `HighlightTheme` 颜色定义存在，无解析器/分词器 | 🔴 严重 |
| 搜索/替换 | 内置 `SearchSession` + `SearchMatcher` | 无 | 🔴 严重 |
| 原生菜单 | macOS AppKit + Win32 NativeMenu | 仅有自定义 `PopupMenu` | 🟡 中等 |
| Dock 布局 | 完整 DockArea/TabGroup/PanelRegistry/序列化 | 无 | 🟡 中等 |
| 文件监视 | `notify` crate 集成 | 无 | 🟡 中等 |
| 国际化 | `rust-i18n` 集成 | 无 | 🟡 中等 |
| WebView | `gpui-wry` 基于 Wry | 无 | 🟢 可选 |
| FPS 监控 | `gpui-fps` 实时 HUD | 无 | 🟢 可选 |
| Chat UI | Message/MessageGroup/Bubble（7种变体） | 无 | 🟢 可选 |
| Markdown 插件 | MarkdownPlugin 扩展系统 | `rgpui-markdown` 基础渲染 | 🟢 可选 |
| Tree 组件 | 虚拟化 Tree + TreeState + 键盘导航 | `tree.rs` 存在但功能待增强 | 🟡 中等 |
| 设置页面 | Setting/SettingGroup/SettingPage | 无 | 🟢 可选 |
| Stepper/评分/描述列表 | 有 | 无 | 🟢 可选 |

## 二、v1.1.0 开发目标

### 高优先级（P0）— 编辑器核心能力

#### 1. LSP 客户端集成 — ✅ 已完成

**目标**: 为 InputState/编辑器提供完整的 LSP 客户端接口，使 ru_editor 等应用能接入语言服务器。

**已完成**（2026-09-04）：
- `LspClient` trait（15 个方法：初始化/关闭/补全/悬停/定义/引用/诊断/语义高亮/代码操作/格式化/重命名/签名帮助/通知）
- 补全子系统：`CompletionProvider`/`CompletionState`/`Completion`/`CompletionMenuOptions`
- 悬停子系统：`HoverProvider`/`HoverState`/`HoverResponse`/`HoverContent`
- 定义跳转：`DefinitionProvider`/`DefinitionLocation`/`DocumentHighlight`/`DocumentHighlightKind`
- 诊断：`DiagnosticsProvider`/`DiagnosticsState`/`DiagnosticEntry`/`DiagnosticTag`
- 语义高亮：`SemanticTokensProvider`/`SemanticTokensState`/`SemanticTokenTypeMap`
- 位置转换：`PositionMapping`（字节偏移 ↔ LSP Position）
- `LspState` 枚举 + `DocumentVersion`
- feature `lsp` 门控，`lsp-types = "0.97.0"`

---

#### 2. 搜索/替换组件 (SearchPanel)

**目标**: 提供内置的搜索/替换面板组件。

**功能**:
- 搜索输入框 + 替换输入框
- 匹配计数显示
- 上一个/下一个匹配导航
- 大小写敏感、全词匹配、正则表达式选项
- 全部替换、替换当前匹配
- `SearchSession` 状态管理
- `SearchMatcher` 匹配引擎

**参考**: gpui-kit `crates/base/src/input/editor/search.rs`

**工作量**: 中（约 1 周）

---

#### 3. Tree-sitter 语法高亮

**目标**: 集成 Tree-sitter，为 CodeEditor 模式提供语法高亮。

**已完成部分**（2026-09-04）：
- `Highlighter` trait 定义（语言/更新/样式/折叠范围）
- `HighlightStyleResolver` trait（语义 token → 样式映射）
- `TextEdit`/`FoldRange` 类型
- `HighlighterFactory` 工厂函数
- `supported_languages()` 列表（23 种语言）

**待完成**：
- Tree-sitter 具体实现（tree-sitter 依赖 + 语言语法包）
- `LanguageRegistry` 语言注册表
- 高亮查询文件管理（`.scm` 文件加载）
- 注入支持（如 HTML 中的 CSS、Markdown 中的代码块）

---

#### 4. 大文件异步加载

**目标**: InputState 支持异步文件加载，避免大文件阻塞 UI。

**功能**:
- `InputState::load_file_async(path)` 异步加载方法
- 加载状态指示（loading spinner）
- 大文件（>10MB）后台读取

**工作量**: 中（约 1 周）

## 五、实施顺序建议

基于依赖关系和优先级，建议按以下顺序实施：

```
Phase 1（alpha）: 无依赖的 API 增强 + SearchPanel
  ├── 全局通知 API（简单，快速见效）
  ├── 统一初始化函数（简单）
  ├── minimize_to_tray（简单）
  ├── 全局窗口管理 API（简单）
  └── SearchPanel（中等，编辑器基础）

Phase 2（beta）: 编辑器核心能力
  ├── Tree-sitter 语法高亮（独立，但 LSP 诊断依赖它）
  ├── LSP 客户端集成（依赖 lsp-types，与 Tree-sitter 并行）
  ├── 大文件异步加载（独立）
  └── StatusBar（独立）

Phase 3（rc）: 编辑器完善 + 桌面增强
  ├── LSP 诊断 + 语义令牌（依赖 Phase 2 的 LSP 基础）
  ├── Tab 虚拟化（依赖 InputState）
  ├── Tab 拖拽排序（独立）
  ├── 原生菜单（独立）
  ├── 文件监视（独立，主题热重载依赖它）
  ├── 国际化（独立）
  ├── 主题热重载（依赖文件监视）
  └── 配置持久化（独立）

Phase 4（release）: 高级功能
  ├── 块级渲染（依赖编辑器基础）
  ├── 虚拟滚动增强（独立）
  ├── 源码映射（依赖块级渲染）
  ├── Markdown 插件（依赖块级渲染）
  ├── Chat UI（独立）
  ├── FPS HUD（独立）
  └── WebView（独立，可选）
```
