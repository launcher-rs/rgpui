# 1.4.0 开发文档（移动端：Android 优先，iOS 预留）

> 实现依据本文档；每项完成后勾选。顺序：文档 → 骨架 → 真机点亮 → 体验对齐 → 发布。
> 库改动统一约定：中文文档注释、零 `#[allow(dead_code)]`、
> 公开 API 进 `prelude`（如适用）、改动包 clippy 干净。
> 本机只有 Android 设备：所有真机验收以 Android 为准；iOS 只做到
> “结构预留 + CI 可验证（`cargo check`）”，不做真机验收。

## 0. 背景与目标

- `rgpui` 目前只有桌面四后端（Windows / macOS / Linux / Web），
  统一入口是 `rgpui-platform::application()` / `current_platform()`。
- 用户只有 Android 设备，1.4.0 目标是在**不破坏桌面端**的前提下，
  让同一套 `rgpui` 应用能跑到 Android 真机上；iOS 结构同步预留。
- 参考实现为 `temp/gpui-mobile`（上游 `gpui-pre 0.3.5` + `wgpu 29` 的
  独立分支，不可直接合入；只借鉴架构）。
- 用户明确希望**好好利用 `rgpui-platform`**：移动端不另起门面，
  统一走 `rgpui-platform` 做 `#[cfg]` 分发。

### 本版本目标（DoD）

1. `docs/1.4.0/` 有完整开发文档（本文档 + README）。
2. 新增 `crates/rgpui-android`（Android 真机实现）与
   `crates/rgpui-ios`（结构预留，iOS 真机以后再验），
   均经 `rgpui-platform::current_platform()` 分发。
3. 新增 `TargetPlatform` / `is_mobile` 等运行时判断 API。
4. 新增 `examples/hello_mobile/`，桌面可 `cargo check`，
   Android 可 `cargo ndk` 出包并在真机点亮空白窗口。
5. CI 新增 Android（`aarch64-linux-android` check + 单测）与
   iOS（`aarch64-apple-ios` check）任务，本机只验 Android 真机。
6. `cargo check --workspace` / `cargo fmt --all` / 改动包 clippy /
   `cargo test --workspace` 全绿；AGENTS.md 完整性清单同步。

### 非目标

- 不做应用商店上架流程（签名、渠道包、各厂商推送）。
- 不做 `PlatformView`（原生 View 嵌入：地图/视频/相机预览）完整实现，
  只预留 trait/注册表位置（见 M3）。
- 不做移动端 IME 全量组合语义（先能弹出键盘 + 提交明文；组合串以后补）。
- 不做无障碍（TalkBack / VoiceOver）、应用内购、离线地图等 Tier 4/5 包。
- 不跟随上游 `gpui`，不合入 `temp/gpui-mobile` 的 `gpui-pre` 快照代码。

## 1. 参考实现调研结论（`temp/gpui-mobile`）

| 主题 | 参考实现做法 | 1.4.0 取舍 |
|------|--------------|------------|
| 总入口 | `gpui_mobile::current_platform(headless)` 按 `target_os` 分发；iOS / Android 各一模块 | 照搬：`rgpui-platform::current_platform()` 增加 `android` / `ios` 分支 |
| Android 入口 | 双路径：`android-activity`（`android_main` 独占线程）+ `host`（Java Activity + `SurfaceView`，自有 render 线程，常驻跨重建） | M1 先 `android-activity` 单路径（简单）；`host` 路径记入 M3 候选 |
| 事件循环 | `poll_events(timeout)` + 延迟任务 `tick()` + vsync 门控 `frame_source`（只在 GPUI 请求帧时绘制） | 照搬三件套，但 `Platform::run` 语义按 `rgpui` 现状适配 |
| 渲染 | `gpui_wgpu::WgpuRenderer` + `CosmicTextSystem`；Android 偏好 Vulkan、回退 GLES；120Hz 按需 `dlsym` 查 `ANativeWindow_setFrameRate` | `rgpui-wgpu` 已是 `wgpu 30` + `cosmic-text 0.19`，直接复用；不锁 GLES 回退细节 |
| 窗口 | `AndroidWindow`（`ANativeWindow` + renderer `Mutex<Option<…>>`）+ `AndroidPlatformWindow: PlatformWindow`；`term_window` 只 `unconfigure_surface` 保图集 | 照搬生命周期语义（INIT/TERM/RESIZE 三态） |
| 输入 | NDK `MotionEvent` → 多点触摸扇出（`DOWN/UP` 只派受影响指针）；`KeyEvent` + JNI `getUnicodeChar` 回填 unicode | M2 落地；M1 先空实现可编译 |
| 键盘/IME | `GpuiInputActivity`（`InputConnection` 多阶段组合）+ `show/hide_keyboard` + `keyboard_height` + `TEXT_INPUT_DIRTY` 强制帧 | M2 先明文提交；组合串/删除环绕记入 M3 |
| 安全区/深浅色 | `content_rect` 算 `SafeAreaInsets`；`Configuration.uiMode_night` 查深浅色；`SystemChromeStyle` 设状态栏/导航栏 | M2 落地安全区 + 深浅色；chrome 样式 M3 |
| 字体/Emoji | 显式加载 `/system/fonts/Roboto*` + `NotoSans*`；Emoji 检测 CBDT，有则用系统，否则读 APK `assets/fonts/NotoColorEmoji.ttf` | 照搬（`swash` 渲 CBDT，不啃 COLR v1） |
| 手势 | `ScrollPhysics::android()`（AOSP `OverScroller` 摩擦样条）+ 动量/惯性模块 | `rgpui` 已有 `scroll_physics.rs`，M3 对齐即可 |
| 运行时判断 | `TargetPlatform::{Android,IOS,MacOS,Linux,Windows,Web}` + `is_mobile()` | M1 落地（放 `rgpui-platform`，核心不膨胀） |
| 包生态 | `packages/*` 按 Flutter 插件逐个 feature 门控（url_launcher / sensors / …） | 本版本最多只做剪贴板/通知/文件选择最小集，其余记候选 |

### 与 `rgpui` 现状的关键差异（移植时注意）

- 参考实现基于 `gpui-pre 0.3.5`：`Platform::restart(binary, args)` 双参、
  `keyboard_mapper() -> Rc<…>` 等签名与 `rgpui 1.3` 不一致，
  **不可整文件复制，只能按 `rgpui::Platform` / `PlatformWindow` /
  `PlatformDisplay` / `PlatformDispatcher` 现行签名逐项实现**。
- `rgpui::Platform::restart` 为单参，`open_window(handle, options)` 语义不变，
  但 Android 原生窗口由系统创建（`INIT_WINDOW`），应用层不得在启动期直接 `open_window`。
- `rgpui-wgpu` 为 `wgpu 30`，参考实现为 `wgpu 29`：surface 配置
  （`WgpuSurfaceConfig` / `PresentMode`）以本仓为准。

## 2. 总体设计（充分利用 `rgpui-platform`）

```text
应用层
  └─ rgpui_platform::application()          # 唯一门面，不写 #[cfg]
       └─ current_platform(headless)
            ├─ windows / macos / linux / web   # 现状不动
            ├─ android → rgpui_android::AndroidPlatform::new()
            └─ ios     → rgpui_ios::IosPlatform::new()   # M1 仅预留

rgpui-android（新 crate）
  ├─ platform.rs    # AndroidPlatform: Platform（执行器/显示器/窗口表/剪贴板最小集）
  ├─ window.rs      # AndroidWindow + AndroidPlatformWindow: PlatformWindow
  ├─ display.rs     # AndroidDisplay: PlatformDisplay
  ├─ dispatcher.rs  # AndroidDispatcher: PlatformDispatcher（ALooper 主队列 + 线程池后台）
  ├─ keyboard.rs    # 键码映射 + 布局（M1 桩，M2 接 JNI）
  ├─ text_system.rs # 复用 rgpui-wgpu::CosmicTextSystem + 系统字体/Emoji 装载（M2）
  ├─ bridge.rs      # android-activity 入口、事件循环、frame_source（M2）
  └─ lib.rs         # current_platform() + TargetPlatform 重导出

rgpui-ios（新 crate，M1 仅桩）
  └─ lib.rs         # IosPlatform 桩：除 text_system 外全默认/host 报错，
                       # 保证 --target aarch64-apple-ios 可 check
```

- `TargetPlatform` / `is_mobile()` / `SystemChromeStyle` 等移动端公共类型
  放在 `rgpui-platform`（`mobile.rs`），`rgpui-android` / `rgpui-ios` 按需引用，
  桌面端零开销。
- 平台特有依赖一律 `target.'cfg(target_os = "...")'.dependencies` 门控，
  主机 `cargo check --workspace` 必须通过；真机依赖（`android-activity` /
  `ndk` / `jni`）只在 Android target 下编译。
- `rgpui` 核心不新增移动端分支（除非 `Platform` 缺可选中性证明必须加默认方法）。

## 7. 架构决策：一平台一 crate + 平台扩展指南

> 结论：不照搬 `temp/gpui-mobile` 的单 crate，沿用本仓“一 OS 一 crate、
> `rgpui-platform` 统一分发”的既定架构。本节记录决策依据，
> 并规定将来扩展新平台（鸿蒙等）时照同一套路加 crate 即可。

### 7.1 为什么不照搬单 crate

`temp/gpui-mobile` 把三层东西装进了一个 crate（实测行数）：

| 部分 | 规模 | 应属层级 |
|------|------|----------|
| `android/` | ~7.7k 行 | 平台实现 |
| `ios/` | ~4.2k 行 | 平台实现 |
| 根共享（`target_platform` / `momentum` / `frame_pacer` / `platform_view`） | ~2k 行 | 移动端公共 infra → 归 `rgpui-platform::mobile` |
| `components/`（glass / material UI 组件） | ~17k 行 | UI 组件 → 归 `rgpui` core，不进 platform 层 |
| `packages/`（url_launcher / sensors / …） | 30 个目录 | 插件生态 → 按需 feature 门控，1.4.0 之后再议 |

对照本仓现状：`rgpui-windows` 13k 行 / `rgpui-macos` 12.7k 行 /
`rgpui-linux` 13.3k 行 / `rgpui-web` 2.7k 行，`rgpui-platform` 仅 157 行纯分发。

决策理由：

1. **单 crate 是外部 fork 的无奈之举**：`gpui-mobile` 作为独立仓库必须发成一个
   `gpui-pre-mobile` 包供外部依赖，合在一起最省事。我们是 workspace monorepo，
   拆 crate 零成本，没必要吃这个亏。
2. **依赖隔离**：`ndk` / `jni` / `android-activity` 只进 `rgpui-android`，
   `objc2` 只进 `rgpui-ios`。单 crate 也能 `cfg` 门控，但 manifest 里多套
   target 依赖堆在一起，review 和排障都难受；每加一个平台就多一块 `cfg`。
3. **独立演进**：本机只有 Android 设备，android 会高频迭代而 ios 基本不动。
   分开后 `rgpui-android` 发版不用带上 `rgpui-ios`；单 crate 则版本号耦合。
4. **增量编译小**：改 Android 不重编 iOS（反之亦然）；CI 可按 target 独立 check。
5. **1.4.0 背不动它的 `components/` + `packages/`**：17k 行 UI 组件与 30 个插件
   本来就不属于 platform 层，不随本次合入。

### 7.2 本版本范围：只做 Android + iOS

- Android：M1 骨架 → M2 真机点亮 → M3 体验对齐（本机可验，全量投入）。
- iOS：M1 结构桩（保证 `--target aarch64-apple-ios check` 通过）→ M4 真实现
  （无真机，只保 CI + 文档，不承诺真机验收）。
- 其他平台（鸿蒙等）：1.4.0 不建 crate、不写实现，只按 §7.3 留好扩展位。

### 7.3 扩展新平台时照此办理（以鸿蒙为例）

1. 新建 `crates/rgpui-ohos`（`Cargo.toml` + `src/rgpui_ohos.rs`），
   实现 `Platform` / `PlatformWindow` / `PlatformDisplay` /
   `PlatformDispatcher`，平台特有依赖一律
   `target.'cfg(...)' .dependencies` 门控，保证主机 `cargo check --workspace` 通过。
2. `TargetPlatform` 加变体（如 `HarmonyOs`）+ `is_*()` 判断，
   `target_platform()` / `DEFAULT_PLATFORM` 跟进 `cfg` 分支。
3. `rgpui-platform` 的 `current_platform()` 加一个 `cfg` 分支；
   `Cargo.toml` 加对应 target 门控依赖。
4. CI 的 `mobile-check` job 加对应 target 的 `cargo check -p rgpui-ohos`。
5. 示例：`examples/hello_mobile/` 能在新平台点亮（或至少可 check），
   AGENTS.md 完整性清单同步新平台条目。
